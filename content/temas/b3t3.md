## El lenguaje SQL y el estándar ANSI/ISO

- **SQL** (*Structured Query Language*): lenguaje declarativo estándar para bases de datos relacionales, basado en el álgebra y el cálculo relacional. Estándar **ANSI/ISO**: SQL-86, SQL-89, **SQL-92 (SQL2)**, **SQL:1999 (SQL3)** —disparadores, recursividad, tipos estructurados, orientación a objetos—, **SQL:2003** (XML, funciones de ventana, `MERGE`, secuencias), SQL:2006, SQL:2008, **SQL:2011** (datos temporales), **SQL:2016** (JSON) y **SQL:2023** (consultas sobre grafos de propiedades).
- **Categorías de sentencias**: **DDL** (`CREATE`, `ALTER`, `DROP`, `TRUNCATE`), **DML** (`INSERT`, `UPDATE`, `DELETE`, `MERGE`), **DQL** (`SELECT`), **DCL** (`GRANT`, `REVOKE`) y **TCL** (`COMMIT`, `ROLLBACK`, `SAVEPOINT`).

## Definición de datos (DDL)

```sql
CREATE TABLE empleado (
  id          INTEGER      PRIMARY KEY,
  dni         CHAR(9)      NOT NULL UNIQUE,
  nombre      VARCHAR(80)  NOT NULL,
  salario     NUMERIC(8,2) DEFAULT 0 CHECK (salario >= 0),
  id_dpto     INTEGER,
  CONSTRAINT fk_dpto FOREIGN KEY (id_dpto) REFERENCES departamento(id)
      ON DELETE SET NULL ON UPDATE CASCADE
);
```

- **Tipos habituales**: `INTEGER/SMALLINT/BIGINT`, `NUMERIC/DECIMAL(p,s)` (exacto), `REAL/FLOAT/DOUBLE PRECISION` (aproximado), `CHAR(n)` (longitud fija), `VARCHAR(n)` (variable), `TEXT/CLOB`, `DATE`, `TIME`, `TIMESTAMP`, `BOOLEAN`, `BLOB`.
- **Restricciones**: `NOT NULL`, `UNIQUE`, `PRIMARY KEY` (única, no nula), `FOREIGN KEY … REFERENCES`, `CHECK`, `DEFAULT`. Acciones referenciales: `CASCADE`, `SET NULL`, `SET DEFAULT`, `RESTRICT`/`NO ACTION`.
- `ALTER TABLE t ADD COLUMN …`, `… DROP COLUMN …`, `… ADD CONSTRAINT …`; `DROP TABLE t`; `CREATE INDEX idx ON t (col)`; `CREATE VIEW v AS SELECT …`.
- **`DELETE` frente a `TRUNCATE` y `DROP`**: `DELETE` borra filas (admite `WHERE`, se registra fila a fila, es transaccional). `TRUNCATE` vacía la tabla entera de forma rápida (sin `WHERE`; en muchos SGBD no se puede deshacer y reinicia los autoincrementales). `DROP TABLE` elimina **la tabla y su estructura**.

## Manipulación de datos (DML)

```sql
INSERT INTO empleado (id, dni, nombre, salario) VALUES (1, '12345678Z', 'Ana', 1800);
INSERT INTO historico SELECT * FROM empleado WHERE salario > 3000;
UPDATE empleado SET salario = salario * 1.03 WHERE id_dpto = 10;
DELETE FROM empleado WHERE id = 1;
```

- `UPDATE` o `DELETE` **sin `WHERE`** afectan a **todas las filas**.
- `MERGE` (SQL:2003) combina `INSERT` y `UPDATE` («upsert») según coincidan o no las claves.

## Consultas (SELECT)

- **Orden de escritura**: `SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY … LIMIT/FETCH`.
- **Orden lógico de evaluación**: `FROM` (y joins) → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `DISTINCT` → `ORDER BY` → `LIMIT/OFFSET`. Por eso un **alias definido en `SELECT` no puede usarse en `WHERE`** (sí en `ORDER BY` en la mayoría de SGBD).
- **Predicados**: `=`, `<>` (o `!=`), `<`, `>`, `BETWEEN a AND b` (**inclusivo**), `IN (…)`, `LIKE` (`%` = cualquier cadena, `_` = un carácter), `IS NULL / IS NOT NULL`, `EXISTS`, `ANY/SOME/ALL`. `AND` tiene más precedencia que `OR`.
- **NULL**: cualquier comparación con `NULL` (`= NULL`) da **desconocido**; se usa `IS NULL`. `NULL + 1` es `NULL`. En un `ORDER BY`, la posición de los nulos depende del SGBD (`NULLS FIRST/LAST`).
- **Funciones de agregación**: `COUNT(*)` (cuenta todas las filas), `COUNT(col)` (**ignora los nulos**), `COUNT(DISTINCT col)`, `SUM`, `AVG`, `MIN`, `MAX`. **Ignoran los `NULL`** (salvo `COUNT(*)`).
- **`GROUP BY`**: agrupa filas; en el `SELECT` solo pueden aparecer las columnas del `GROUP BY` y funciones de agregación. **`WHERE` filtra filas antes de agrupar; `HAVING` filtra grupos después** (y puede usar agregaciones).

```sql
SELECT d.nombre, COUNT(*) AS n, AVG(e.salario) AS media
FROM empleado e JOIN departamento d ON d.id = e.id_dpto
WHERE e.salario > 1000
GROUP BY d.nombre
HAVING COUNT(*) >= 3
ORDER BY media DESC
FETCH FIRST 5 ROWS ONLY;   -- LIMIT 5 en MySQL/PostgreSQL; TOP 5 en SQL Server
```

### Reuniones (JOIN)

| Tipo | Resultado |
|---|---|
| **INNER JOIN** | Solo filas con coincidencia en ambas tablas |
| **LEFT [OUTER] JOIN** | Todas las filas de la izquierda; `NULL` en las de la derecha sin coincidencia |
| **RIGHT [OUTER] JOIN** | Todas las filas de la derecha |
| **FULL [OUTER] JOIN** | Todas las filas de ambas |
| **CROSS JOIN** | Producto cartesiano (n × m filas); también se obtiene si se **omite la condición** de reunión |
| **NATURAL JOIN** | Une por las columnas de igual nombre |
| **Autorreunión (*self join*)** | Una tabla consigo misma con alias distintos |

> [!TRUCO] «Clientes **sin** pedidos»: `LEFT JOIN` y filtrar `WHERE p.id IS NULL`, o `NOT EXISTS`. Ojo con `NOT IN` si la subconsulta puede devolver `NULL`: **no devuelve ninguna fila**.

### Subconsultas, conjuntos y CTE

- **Subconsulta escalar** (un valor), **de fila**, **de tabla** (en `FROM`, *tabla derivada*) y **correlacionada** (referencia a la consulta externa; se evalúa por cada fila).
  - `WHERE salario > (SELECT AVG(salario) FROM empleado)`; `WHERE EXISTS (SELECT 1 FROM pedido p WHERE p.cliente = c.id)`.
  - `ALL`: la condición debe cumplirse con todos; `ANY/SOME`: con alguno.
- **Operadores de conjuntos** (mismo número de columnas y tipos compatibles): `UNION` (**elimina duplicados**), `UNION ALL` (los conserva; más rápido), `INTERSECT`, `EXCEPT` (`MINUS` en Oracle).
- **CTE** (*Common Table Expression*): `WITH ventas AS (SELECT …) SELECT … FROM ventas`; admiten **recursividad** (`WITH RECURSIVE`) para jerarquías.

### Funciones

- **Cadenas**: `CONCAT`/`||`, `SUBSTRING`, `UPPER`, `LOWER`, `TRIM`, `LENGTH`, `REPLACE`. **Numéricas**: `ROUND`, `CEIL`, `FLOOR`, `ABS`, `MOD`. **Fecha**: `CURRENT_DATE`, `EXTRACT(YEAR FROM f)`.
- **Conversión y nulos**: `CAST(x AS tipo)`, `COALESCE(a, b, …)` (primer valor no nulo), `NULLIF(a, b)` (nulo si son iguales), `CASE WHEN … THEN … ELSE … END`.
- **Funciones de ventana** (SQL:2003): se calculan sobre un conjunto de filas **sin colapsarlas**: `ROW_NUMBER()`, `RANK()` (deja huecos tras empates), `DENSE_RANK()` (sin huecos), `SUM(x) OVER (PARTITION BY d ORDER BY f)`, `LAG/LEAD`.

## Vistas, seguridad y transacciones

- **Vista**: consulta almacenada con nombre; ofrece **seguridad** (exponer solo columnas o filas), **simplicidad** e **independencia lógica**. `WITH CHECK OPTION` impide modificaciones que dejen filas fuera de la vista. Las vistas simples (una tabla, sin agregados) son actualizables.
- **DCL**: `GRANT SELECT, UPDATE ON t TO usuario [WITH GRANT OPTION]`; `REVOKE …`; **roles**. Principio de **mínimo privilegio**.
- **TCL**: `BEGIN/START TRANSACTION`, `COMMIT`, `ROLLBACK`, `SAVEPOINT s` / `ROLLBACK TO s`; `SET TRANSACTION ISOLATION LEVEL …`. Algunos SGBD hacen **commit implícito** con sentencias DDL.
- **Inyección SQL**: se previene con **consultas parametrizadas** (`PreparedStatement`), validación y mínimos privilegios, nunca concatenando entradas del usuario en la sentencia.

## Procedimientos almacenados y funciones

- Un **procedimiento almacenado** es un subprograma guardado y compilado en el servidor, que se ejecuta con `CALL` / `EXEC`. Admite parámetros `IN`, `OUT` e `INOUT`. Una **función almacenada** **devuelve un valor** y puede usarse dentro de un `SELECT`.
- **Ventajas**: menos tráfico cliente-servidor, planes de ejecución reutilizados, **reutilización de lógica**, **seguridad** (se concede `EXECUTE` sin acceso a las tablas). **Inconvenientes**: menor portabilidad (cada SGBD tiene su dialecto), dificultad de depuración y versionado, lógica de negocio repartida.
- **Lenguajes procedimentales**: **PL/SQL** (Oracle), **T-SQL** (SQL Server), **PL/pgSQL** (PostgreSQL), **SQL/PSM** (estándar; MySQL/MariaDB, Db2).
- **Elementos**: variables (`DECLARE`), condicionales (`IF … THEN … ELSE`), bucles (`LOOP`, `WHILE`, `FOR`), **cursores** (`DECLARE CURSOR`, `OPEN`, `FETCH`, `CLOSE`: recorren un resultado fila a fila; deben usarse con moderación porque son lentos frente a las operaciones por conjuntos) y **manejo de excepciones** (`EXCEPTION WHEN …` en PL/SQL; `TRY … CATCH` en T-SQL).

```sql
CREATE PROCEDURE subir_sueldo (IN p_dpto INT, IN p_pct DECIMAL(5,2))
BEGIN
  UPDATE empleado SET salario = salario * (1 + p_pct/100) WHERE id_dpto = p_dpto;
END;
```

## Disparadores (triggers) y eventos

- **Disparador**: bloque de código asociado a una tabla (o vista) que se ejecuta **automáticamente** ante un evento `INSERT`, `UPDATE` o `DELETE`. No se invoca manualmente ni recibe parámetros ni devuelve valores.
- **Momento**: `BEFORE` (antes; permite validar o modificar los datos entrantes), `AFTER` (después) e `INSTEAD OF` (sustituye la operación; típico en vistas). **Nivel**: `FOR EACH ROW` (una vez por fila) o `FOR EACH STATEMENT` (una vez por sentencia).
- **Valores antiguo y nuevo**: `OLD` y `NEW` (MySQL, PostgreSQL, Oracle con `:OLD`/`:NEW`); `inserted` y `deleted` (SQL Server). En un `INSERT` solo existe `NEW`; en un `DELETE` solo `OLD`.
- **Usos**: **auditoría** (histórico de cambios), reglas de integridad complejas, cálculo de campos derivados, replicación. **Cuidados**: efectos en cascada y recursión, impacto en el rendimiento y mantenimiento «invisible».

```sql
CREATE TRIGGER trg_audit AFTER UPDATE ON empleado
FOR EACH ROW
  INSERT INTO auditoria(id_emp, antes, despues, fecha)
  VALUES (OLD.id, OLD.salario, NEW.salario, CURRENT_TIMESTAMP);
```

- **Eventos programados**: tareas planificadas en el servidor (`CREATE EVENT` en MySQL, `DBMS_SCHEDULER` en Oracle, *SQL Server Agent*, `pg_cron`). Se ejecutan por tiempo, no por modificaciones de datos.

## Rendimiento

- **Índices** sobre columnas de `WHERE`, `JOIN` y `ORDER BY`; evitar **funciones sobre la columna** en el `WHERE` (`WHERE YEAR(fecha) = 2025` impide usar el índice) y el `SELECT *` innecesario; revisar el plan con `EXPLAIN`.
- Preferir operaciones **por conjuntos** a cursores, `EXISTS` a `IN` con subconsultas grandes, y `UNION ALL` a `UNION` cuando no hay duplicados.
