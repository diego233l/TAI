// Tema 18 (B3·T4) · Diseño y programación orientada a objetos. Patrones de diseño y UML

? ¿Cuál de los siguientes NO es uno de los cuatro pilares de la programación orientada a objetos?
a) Normalización
b) Abstracción
c) Encapsulamiento
d) Polimorfismo
= a
> Los pilares son abstracción, encapsulamiento, herencia y polimorfismo. La normalización pertenece al diseño de bases de datos.
@ POO

? ¿Qué es una clase en POO?
a) Una instancia concreta de un objeto
b) Una plantilla que define atributos y métodos de un conjunto de objetos
c) Un método especial
d) Una variable global
= b
> Un objeto es una instancia de una clase.
@ POO

? ¿Qué es el encapsulamiento?
a) Heredar atributos de otra clase
b) Sobrecargar un método
c) Crear instancias de una clase
d) Ocultar el estado interno de un objeto y exponer una interfaz pública controlada
= d
> Se implementa con modificadores de acceso (private, protected, public) y métodos de acceso.
@ POO

? ¿Qué modificador de acceso impide que una subclase acceda directamente a un atributo de la superclase, pero lo permite dentro de la propia clase?
a) public
b) protected
c) static
d) private
= d
> private limita el acceso a la propia clase; protected lo extiende a subclases (y al paquete en Java).
@ POO

? La sobrecarga (overloading) de métodos consiste en:
a) Definir varios métodos con el mismo nombre y distinta lista de parámetros
b) Redefinir en la subclase un método heredado con la misma firma
c) Heredar de varias clases
d) Declarar un método como estático
= a
> Se resuelve en tiempo de compilación.
@ Polimorfismo

? La sobrescritura (overriding) de métodos consiste en:
a) Definir métodos con el mismo nombre y distinto número de parámetros
b) Eliminar un método heredado
c) Declarar métodos privados
d) Redefinir en la subclase un método de la superclase con la misma firma
= d
> Se resuelve en tiempo de ejecución mediante enlace dinámico.
@ Polimorfismo

? ¿Cuándo se resuelve el polimorfismo por sobrescritura?
a) En tiempo de compilación
b) En el enlazado
c) En el diseño
d) En tiempo de ejecución (enlace dinámico)
= d
> La máquina virtual selecciona la implementación según la clase real del objeto.
@ Polimorfismo

? ¿Puede una clase en Java heredar de dos clases?
a) No, Java solo permite herencia simple de clases (aunque puede implementar varias interfaces)
b) Sí, siempre
c) Sí, pero solo si son abstractas
d) Solo en Java 8
= a
> C++ y Python sí admiten herencia múltiple de clases.
@ Herencia

? ¿Qué característica tiene una clase abstracta?
a) Debe tener todos sus métodos abstractos
b) No puede tener atributos
c) No puede instanciarse directamente
d) No puede ser heredada
= c
> Puede combinar métodos abstractos y concretos.
@ Clases abstractas

? ¿Qué diferencia fundamental hay entre una interfaz y una clase abstracta (clásicamente)?
a) No hay diferencia
b) La interfaz puede instanciarse
c) La interfaz define un contrato de métodos sin estado de instancia; una clase abstracta puede tener atributos y código
d) La clase abstracta no admite métodos
= c
> Una clase puede implementar varias interfaces, pero heredar de una sola clase abstracta (en Java).
@ Interfaces

? La relación «un coche tiene un motor, y el motor no existe sin el coche» es una:
a) Agregación
b) Herencia
c) Dependencia
d) Composición
= d
> En la composición las partes dependen del ciclo de vida del todo.
@ Relaciones

? En una relación de agregación:
a) Las partes no pueden existir independientemente del todo
b) No hay relación todo-parte
c) Es lo mismo que herencia
d) Las partes pueden existir de forma independiente del todo
= d
> Ejemplo: un departamento agrega empleados; los empleados siguen existiendo si el departamento desaparece.
@ Relaciones

? ¿Qué pregunta ayuda a decidir entre herencia y composición?
a) ¿Es un? (herencia) frente a ¿tiene un? (composición)
b) ¿Es rápido?
c) ¿Es privado?
d) ¿Es estático?
= a
> Un perro «es un» animal; un coche «tiene un» motor.
@ Relaciones

? ¿Qué se persigue con «bajo acoplamiento y alta cohesión»?
a) Módulos muy dependientes entre sí
b) Clases grandes con muchas responsabilidades
c) Eliminar las interfaces
d) Módulos independientes entre sí y con una única responsabilidad bien definida
= d
> Facilita el mantenimiento y la reutilización.
@ Diseño

? ¿Qué principio SOLID afirma que una clase debe tener una única razón para cambiar?
a) Single Responsibility
b) Open/Closed
c) Liskov Substitution
d) Dependency Inversion
= a
> S: una clase, una responsabilidad.
@ SOLID

? ¿Qué enuncia el principio abierto/cerrado (Open/Closed)?
a) Las entidades software deben estar abiertas a la extensión y cerradas a la modificación
b) Las clases deben estar siempre abiertas
c) Los ficheros deben cerrarse siempre
d) No se pueden extender las clases
= a
> Se consigue con abstracciones y polimorfismo.
@ SOLID

? El principio de sustitución de Liskov establece que:
a) Las clases deben tener un solo método
b) Debe usarse siempre herencia múltiple
c) Los métodos deben ser estáticos
d) Los objetos de un subtipo deben poder reemplazar a los de su tipo base sin alterar el correcto funcionamiento
= d
> Un cuadrado que hereda de rectángulo y rompe el comportamiento esperado viola LSP.
@ SOLID

? ¿A qué letra de SOLID corresponde «depender de abstracciones y no de concreciones»?
a) D
b) S
c) O
d) I
= a
> Dependency Inversion Principle.
@ SOLID

? ¿Qué mide el término «cohesión» en un módulo?
a) El grado de dependencia con otros módulos
b) El tamaño en líneas de código
c) El tiempo de ejecución
d) El grado en que los elementos del módulo están relacionados entre sí y con su propósito
= d
> Una alta cohesión es deseable; el acoplamiento debe ser bajo.

@ Patrones

? El patrón Singleton garantiza que:
