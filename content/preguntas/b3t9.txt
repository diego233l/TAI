// Tema 23 (B3·T9) · Repositorios, control de versiones, metodologías, pruebas y desarrollo colaborativo

? ¿Cuál de los siguientes es un sistema de control de versiones centralizado?
a) Git
b) Mercurial
c) Subversion (SVN)
d) Bazaar distribuido
= c
> En SVN existe un repositorio central con números de revisión globales; Git y Mercurial son distribuidos.
@ Control de versiones

? ¿Qué ventaja principal ofrece un sistema de control de versiones distribuido como Git?
a) Cada desarrollador dispone de una copia completa del historial y puede trabajar sin conexión
b) Solo hay un repositorio y no admite ramas
c) Impide el trabajo en paralelo
d) No permite recuperar versiones anteriores
= a
> Las ramas son baratas y las operaciones habituales son locales.
@ Git

? En Git, ¿cuál es el flujo básico para registrar un cambio y publicarlo?
a) git push → git commit → git add
b) git commit → git add → git pull
c) git add → git commit → git push
d) git clone → git add → git fetch
= c
> add prepara en el área de staging, commit crea la instantánea local y push la envía al remoto.
@ Git

? ¿Qué hace «git fetch»?
a) Descarga e integra los cambios en la rama actual
b) Envía commits al remoto
c) Descarga los cambios del remoto sin integrarlos en la rama actual
d) Crea una rama nueva
= c
> git pull equivale a fetch + merge (o rebase).
@ Git

? ¿Qué hace «git pull»?
a) git fetch seguido de git merge (o rebase) de los cambios remotos
b) Envía cambios al remoto
c) Deshace el último commit
d) Borra la rama local
= a
> Puede generar conflictos que hay que resolver.
@ Git

? ¿Para qué sirve el área de preparación (staging area o index) de Git?
a) Para almacenar copias de seguridad
b) Para seleccionar qué cambios formarán parte del próximo commit
c) Para publicar al servidor
d) Para compilar el proyecto
= b
> Se alimenta con git add.
@ Git

? ¿Qué diferencia hay entre git merge y git rebase?
a) merge integra ramas creando (normalmente) un commit de fusión; rebase reaplica commits sobre otra base, produciendo historial lineal
b) rebase crea siempre un commit de fusión
c) merge reescribe todos los commits
d) Son idénticos
= a
> No debe hacerse rebase de ramas ya publicadas y compartidas.
@ Git

? ¿Qué comando deshace un commit ya publicado creando un nuevo commit inverso, sin reescribir el historial?
a) git reset --hard
b) git rebase -i
c) git stash
d) git revert
= d
> reset --hard descarta cambios y mueve la rama; es peligroso en ramas compartidas.
@ Git

? ¿Qué hace «git stash»?
a) Borra los cambios
b) Guarda temporalmente los cambios sin confirmar para recuperarlos después
c) Publica la rama
d) Crea una etiqueta
= b
> Es útil para cambiar de rama sin hacer commit.
@ Git

? ¿Qué es un conflicto de fusión (merge conflict)?

c) Un commit sin mensaje
d) Una situación en la que Git no puede integrar automáticamente cambios que afectan a las mismas líneas

> Hay que resolverlo manualmente y confirmar el resultado.
